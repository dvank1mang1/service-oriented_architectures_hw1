# ADR-0002: Синхронное ядро checkout и асинхронное распространение событий

- Статус: принято
- Дата: 2026-10-02

## Контекст

При оформлении нельзя подтвердить заказ без проверки актуальной цены и
резервирования остатка. При этом построение ленты и отправка уведомлений не
должны увеличивать задержку checkout. Межсервисной ACID-транзакции нет.

## Решение

Order Service синхронно вызывает Catalog Service для проверки снимка цены и
резерва, а Payment Service — для создания платёжного намерения. Дальнейшие
изменения статусов публикуются как события. Feed и Notification обрабатывают
их асинхронно.

При реализации каждый владелец данных будет атомарно сохранять изменение и
outbox-запись в своей БД. Публикатор доставит событие как минимум один раз;
потребители будут дедуплицировать его по `event_id`. Для checkout будут нужны
идемпотентные команды и компенсирующие действия: снять резерв при неуспешной
оплате, инициировать возврат при невозможности подтвердить заказ.

## Последствия

Путь оформления остаётся согласованным там, где это заметно пользователю, а
лента и уведомления не блокируют его. Цена решения — временная рассогласованность
read-моделей и более сложная обработка повторов и сбоев.
